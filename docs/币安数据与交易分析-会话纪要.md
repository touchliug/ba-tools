## 一、排障：两个生产问题

### 1.1 `openInterestHist` 稳定返回 400

**现象**

```
Request failed: https://fapi.binance.com/futures/data/openInterestHist
  ?symbol=CTUSDT&period=1h&limit=500&startTime=...&endTime=... - status: 400
```

**定位**：URL 里 `endTime − startTime = 2,592,000,000 ms`，正好等于 `30 × 86400 × 1000`，精确到毫秒。

**根因**：代码用 `now − 30 天` 作为窗口起点，正好卡在币安「只保留最近 30 天、且按服务器时钟校验」的红线上。本地 `now` 取样到请求真正到达之间隔着线程错峰（100ms × 序号）、重试、网络 RTT —— 窗口必然变成「30 天 + ε」，于是稳定 400。

**影响**：启动校验对 540 个币逐个重试 1h OI 回补，全部失败 → 数据永远补不上 → 每次启动再失败一遍，白刷配额。

**修复**（`DataInitializer`）：

```java
static long oiWindowStart(long now, int days) {
    long wanted = now - (long) days * DAY_MS;
    long floor  = now - 30 * DAY_MS + 2 * HOUR_MS;   // 留 2 小时余量
    return Math.max(wanted, floor);
}
```

配 3 个单测锁住边界（窗口恒 ≤ 30 天、30 天保留 2h 余量、小天数不被裁剪）。

**附带修复**：失败日志原来只打 `status: 400`，把币安返回的 `{"code":...,"msg":...}` 丢掉了 —— 这是这次排查绕远路的主要原因。现在打 body（截断 200 字符）。

### 1.2 `Used weight 2045 >= soft limit 2000`

**含义**：限速自保护触发，不是错误。客户端读到 `X-MBX-USED-WEIGHT-1M` 后，若超过软上限 2000，就把全局冷却推到 `now + 3s`，所有线程暂停。

**根因**：1h K 线的 `limit=744`（启动回补）/`800`（定时任务）都落在币安权重表的 **5 档**（501–1000），500 个币 = 2500 权重，一分钟内必然撞破 2400 的硬顶。

**结论**：这是保护机制在正常工作。真要削峰，把 1h 的 limit 压到 500 以内（权重降到 2），或把 `request-interval-ms` 从 100 放到 150–200。**本次未改动**——因为降 limit 会牺牲 30 天回看深度，反而让启动校验永远判「缺数据」。

## 三、数据分析结论

### 3.1 「5 连跌后第 6/7 天上涨」概率

| 指标 | 150 天数据 | 3 年数据 |
|---|---|---|
| 事件数 | 1312 | **5984** |
| P(第 6 天涨) | 58.2% | **53.7%** |
| P(第 7 天涨 \| 第 6 天涨) | 47.8% | 49.2% |
| 两天都涨 | 28.0% | 26.4% |
| 基线 P(任意一天涨) | 47.1% | 47.15% |
| 独立交易日 | 129 | 681 |
| 95% CI（按日期聚类） | [48%, 67%] | **[47%, 60%]** |

**结论**：58% 是小样本幻觉。补到 3 年后回落到 53.7%，置信区间依然覆盖基线 —— **不构成策略**。

**方法论要点**：
- 事件高度同日聚集（最极端的一天 184 个币同时触发），不能按 1312 算自由度，必须按**日期**做聚类 bootstrap
- 「恰好 5 连跌」不能当事件 —— 那等于预设第 6 天不会跌（第一版因此得出 99.2% 的假结果）
- 平盘（close == prev close）要算作中断，占 0.4%

## 四、市场结构认知

### 4.1 名义多空比是什么

**名义 = notional = 仓位按现价折算的 USDT 敞口**。所以名义多空比 = 多头名义价值 ÷ 空头名义价值，衡量「钱」而不是「人」。

同一个市场，两种口径会得出相反结论：

| 口径 | 算法 | 例子 | 结论 |
|---|---|---|---|
| 账户数多空比 | 95 ÷ 5 | 19.0 | 散户一边倒做多 |
| 名义多空比 | 120 万 ÷ 380 万 | 0.32 | 钱其实压在空头 |

币安四个接口对应关系：

| 接口 | 口径 | 库里 `ratio_type` |
|---|---|---|
| `globalLongShortAccountRatio` | 全市场账户数 | `GLOBAL_ACCOUNT` |
| `topLongShortAccountRatio` | 大户账户数 | `TOP_ACCOUNT` |
| `topLongShortPositionRatio` | 大户持仓量（名义） | `TOP_POSITION` |
| `takerlongshortRatio` | 主动买卖成交额 | `TAKER` |

**坑**：第三个接口返回的字段也叫 `longAccount`/`shortAccount`，但语义是按持仓量加权的占比，不是账户数。

### 4.2 强平是被使用的工具，不是对手

核心机制：**强平看标记价格（现货指数 + 基差），不是最新成交价**。现货盘子通常只有合约的几分之一，所以在现货端用很小的钱就能把指数砸下去，合约端成片的多头被平仓 —— 这就是「插针」的物理机制。

四种手法：

| 手法 | 做法 | 你看到的信号 |
|---|---|---|
| 推标记价 | 在现货端砸/拉 | 合约没量，价格却瞬间跳 |
| 打流动性空档 | 挑凌晨、周末动手 | 凌晨 2–4 点的长上影/下影 |
| 诱饵式建仓 | 先拉到「看起来安全」的位置 | 滞涨 + 散户比骤降 |
| 撤挂单造假墙 | 关键位挂大单又抽走 | 挂单墙突然消失 |

**数据指纹**（AINUSDT 实测）：价格单小时跌 8–20% 的 12 个小时，OI 平均**上升 4.76%**（空头在加仓），随后 24 小时平均 **+38.66%**。这就是「砸盘诱空 → 反弹爆空」的统计形态。

### 4.3 浮盈如何落袋

29M 的浮盈不是钱，是「按最后一笔成交价估出来的标签」。真正的落袋只有卖出，而卖出的价格取决于有多少人**被迫买入**：

| 平均出货价 | 实际到手（vs 1647 万浮盈） | 转化率 |
|---|---|---|
| 0.1406（零滑点） | 16.47M | 100% |
| 0.12 | 12.2M | 74% |
| 0.10 | 8.1M | 49% |
| 0.08 | 4.0M | 24% |

所以最优路径不是自己砸盘，而是**制造空头爆仓**，用那些不计成本的市价买单接货。

### 4.4 OI 字段的真实语义

| 字段 | 含义 | 单位 | 状态 |
|---|---|---|---|
| `open_interest` | 单币实时快照 | 基础币 | **全表 100% 为 NULL**（191 万行） |
| `sum_open_interest` | 持仓总量 | 基础币 | 有值 |
| `sum_open_interest_value` | 持仓名义价值 | USDT | 有值 |

`open_interest` 恒空的原因：写入路径只走 `openInterestHist`，那个接口没有 `openInterest` 字段；`getOpenInterest()` 方法从未被调用。

**关键区别**：`sum_open_interest_value` = 币数 × 价格，价格涨 10% 它就涨 10%，**不能用来判断仓位变化**。判断加仓/减仓看 `sum_open_interest`（币数）。

校验方法：`sum_open_interest_value ÷ sum_open_interest` 应等于当时的隐含单价（AIN 0.29118 vs 收盘 0.28719，差 1.4%；BTC 78,313，吻合）。

## 五、庄家拉币六段流程

| 阶段 | 核心动作 | 盘面/数据特征 | AIN 实证 |
|---|---|---|---|
| ① 选品 | 挑低流通、深度浅、无强庄的合约 | OI/成交额低、盘口薄、费率≈0 | 0.03–0.04 横盘，日成交 1–8M |
| ② 吸筹 | 低位压价、挂大单吃恐慌盘 | 价格横、OI 缓升、费率微正 | 10-24~25，OI 9.4M→10.0M |
| ③ 试盘 | 拉 10–20% 再砸回，洗浮筹 | 长上影、OI 骤增骤减 | 10-26 12:00–16:00 |
| ④ 拉升 | 市价扫穿卖墙、打爆空头 | OI 与价格同涨、费率转正 | 0.05→0.17，OI 10M→56M |
| ⑤ 派发 | 借空头爆仓的买盘挂单出货 | 价格滞涨、OI 见顶、成交额萎缩 | 卡 0.145，OI 回落，成交 722M→43M |
| ⑥ 砸盘 | 撤买墙、引爆多头连环爆仓 | OI 断崖、价格瀑布、费率转负 | — |

**本质**：庄家赚的不是方向，是**杠杆差**和**流动性差** —— 用别人的强平单当自己的出货通道。

### 阶段识别（已工具化）

五组特征：**价（斜率）、量（量比）、仓（OI 币数）、费（资金费率）、人（散户/大户背离）**。

| 阶段 | 判定阈值（节选） |
|---|---|
| 砸盘 | 24h 跌 >12%，OI 24h 降 >4%，距高 < -20% |
| 拉升 | 24h 涨 >10% 且距高 > -25%，OI > +5%，量比 >1.5 |
| 派发 | 距高 > -8%，OI 距峰 < -5%，量比 <0.6，费率 >0.02% |
| 试盘 | 振幅 >12%，\|24h\| < 6%，量比 >2 |
| 吸筹 | \|7d\| < 8%，量比 <0.8，OI 7d 增，费率 ≤0.01% |

优先级：`砸盘 > 拉升 > 派发 > 试盘 > 吸筹`，最高分低于阈值归「冷却」。

> **2026-11-05 更正**：上面这套阈值是 v1（全市场绝对值），已废弃。v2 改为
> **自身 90 天 z-score**，并加入多周期一致性、BTC 超额、证伪条件。
>
> 更重要的是：v2 配了回测（`ba-tools backtest`），结论是**阶段标签没有预测力** ——
> 六个阶段的 7 日表现与基线相差均在 ±1pp 内，按交易日聚类后置信区间全部跨 0。
> 因此它只能当「状态描述 + 异常排查」用，不能当交易信号。
> 详见 `ba-tools/README.md` 与 `单币分析SOP.md` 附录。

## 七、本次踩过的三个坑（都记下来）

### 坑 1：构造性偏差 —— 99.2% 的假胜率

第一版把「恰好 5 连跌」当事件。这等于**预设第 6 天不会下跌**（连跌在第 5 天结束，第 6 天必然不是跌），于是算出 99.2% 的上涨概率。

**修正**：事件定义为「第 5 个连续下跌日」，之后不做任何选择性剔除 —— 连跌继续就让它继续，结果如实计入。

### 坑 2：分母不同源 —— 59% / 6% / 45.9M 全部作废

用「跨所鲸鱼仓位 ÷ 币安单所 OI」算出了三个数，被指出数据是聚合后全部撤回。

**教训**：分子和分母必须同源。第三方数据只能当旁证，不能参与计算。

**修正后的做法**：用币安自己的 `TOP_POSITION`（1.67）重算，结论从「94% 空头在散户手里」改成「多头高度集中、空头高度分散」。

### 坑 3：没看清值的形式就下结论

看到 `password:` 有值就断言「明文密码泄露风险」，实际是 `${DB_PASSWORD}` 占位符。

**教训**：判断前先看值的形态，别只看「有没有值」。

## 附录：常用 SQL

```sql
-- 数据覆盖
SELECT `interval`, COUNT(*) rows_, COUNT(DISTINCT symbol) syms,
       FROM_UNIXTIME(MIN(open_time)/1000) first_dt,
       FROM_UNIXTIME(MAX(open_time)/1000) last_dt
FROM klines GROUP BY `interval`;

-- 价格 + 主动买占比 + OI 三合一
SELECT FROM_UNIXTIME(k.open_time/1000) t,
       CAST(k.`close` AS DECIMAL(20,6)) px,
       ROUND(100*CAST(k.taker_buy_quote AS DECIMAL(30,2))
             /CAST(k.quote_asset_volume AS DECIMAL(30,2)),1) buy_pct,
       ROUND(CAST(o.sum_open_interest AS DECIMAL(30,0))/1e6,1) oi_coin_m,
       ROUND(CAST(o.sum_open_interest_value AS DECIMAL(30,2))/1e6,1) oi_usd_m
FROM klines k
LEFT JOIN open_interest o
  ON o.symbol=k.symbol AND o.period='1h' AND o.`timestamp`=k.open_time
WHERE k.symbol='AINUSDT' AND k.`interval`='1h'
ORDER BY k.open_time DESC LIMIT 24;

-- 大户 vs 散户背离
SELECT FROM_UNIXTIME(`timestamp`/1000) t, ratio_type,
       ROUND(CAST(long_short_ratio AS DECIMAL(20,4)),3) ratio
FROM long_short_ratio
WHERE symbol='AINUSDT' AND period='1h'
  AND ratio_type IN ('TOP_POSITION','GLOBAL_ACCOUNT')
ORDER BY `timestamp` DESC LIMIT 20;
```
