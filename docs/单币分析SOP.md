# 单币分析 SOP

> 拿到一个币（比如有人喊单、或者从涨幅榜看到），按这个流程走一遍。
> 分三档：**3 分钟快速分诊** / **10 分钟标准评估** / **30 分钟完整尽调**。
> 所有命令基于 `ba-tools`，数据来自自己的库，不依赖第三方。

---

## 第 0 步：能不能分析（10 秒）

```bash
java -jar ba-tools.jar stage --symbol XXXUSDT
```

没输出数据 = 库里没有这个币（新上市 / 已下架），直接跳过。

**三个前置判断**：

| 检查 | 方法 | 影响 |
|---|---|---|
| 上市多久 | `SELECT MIN(open_time) FROM klines WHERE symbol='X' AND interval='1d'` | < 30 天 → 没有历史分位，结论打折 |
| 数据够不够 | 上面命令的 `bars` 数 | < 72 根 → 不分析 |
| 有没有 OI | 输出里 OI 是数字还是 0 | 没 OI 就少了最重要的维度 |

---

## 第 1 步：阶段定位（30 秒，必做）

```bash
java -jar ba-tools.jar stage --symbol XXXUSDT
```

输出包含：现价、24h/7d 涨跌、量比、24h 振幅、距 14 天高点、OI 24h/7d/距峰、大户持仓比、散户比 72h 变化、判定 + 证据。

| 判定 | 含义 | 动作 |
|---|---|---|
| **吸筹** | 价格横、地量、仓缓升、费率≈0 | 加入观察池，等放量 |
| **试盘** | 大幅振荡但净变动小 | 等突破方向确认 |
| **拉升** | 价仓同涨、放量、费率转正 | 已迟到，评估剩余空间（见第 5 步） |
| **派发** | 滞涨、仓减、量萎、费率仍高 | 不参与；持有者准备离场 |
| **砸盘** | 价崩 + 仓崩 | 不接刀，等企稳（通常 24–48h） |
| **冷却** | 结构不清 | 跳过 |

---

## 第 2 步：结构三问（2 分钟）

### Q1：价格在什么位置？

```sql
SELECT MAX(CAST(high AS DECIMAL(30,10))) hi, MIN(CAST(low AS DECIMAL(30,10))) lo
FROM klines WHERE symbol='X' AND `interval`='1d' AND open_time > UNIX_TIMESTAMP(NOW()-INTERVAL 90 DAY)*1000;
```

现价落在 90 天区间的哪个分位。**> 80% 分位 = 高位**，< 20% = 低位，中间 = 尴尬区。

### Q2：仓位在增还是减？

看 `sum_open_interest`（**币数**，不是 USD）。

- OI 24h 和 7d 同向上升 → 新钱在进
- 24h 降、7d 升 → 短期在撤，趋势还在
- 双降 → 趋势结束

### Q3：量在放大还是萎缩？

量比 = 24h 成交额 ÷ 前 6 天日均。**> 2 = 放量，< 0.6 = 地量**。

### 三者组合矩阵

| 价格 | OI | 量比 | 含义 |
|---|---|---|---|
| 涨 | 升 | >1.5 | 新多进场，真拉升 ✅ |
| 涨 | 降 | >1.5 | 空头平仓推动，虚火 ⚠️ |
| 涨 | 升 | <0.6 | 缩量上涨，没人接力 ⚠️ |
| 横 | 升 | <0.8 | 悄悄建仓（吸筹特征）✅ |
| 横 | 降 | 任意 | 有人在撤，等方向 ⚠️ |
| 跌 | 升 | >1.5 | 新空进场，还有下跌空间 ❌ |
| 跌 | 降 | >1.5 | 多头止损/爆仓，接近底部 ⚠️ |

## 第 3 步：拥挤度（1 分钟）

```sql
SELECT ratio_type, ROUND(CAST(long_short_ratio AS DECIMAL(20,4)),3) r,
       ROUND(CAST(long_value AS DECIMAL(20,4)),4) long_side,
       ROUND(CAST(short_value AS DECIMAL(20,4)),4) short_side
FROM long_short_ratio
WHERE symbol='X' AND period='1h'
  AND `timestamp` = (SELECT MAX(`timestamp`) FROM long_short_ratio WHERE symbol='X' AND period='1h')
ORDER BY ratio_type;
```

| 指标 | 怎么读 |
|---|---|
| `TOP_POSITION` > 1.5 | 大户持仓偏多（钱在多头） |
| `GLOBAL_ACCOUNT` < 0.5 | 散户账户偏空（人多在空头） |
| 两者背离 = 典型的「人少钱多 vs 人多钱少」 | 空头容易被挤 |
| `TAKER` > 1 | 近期主动买占优 |

> ⚠️ **口径提醒**：`GLOBAL_ACCOUNT` / `TOP_ACCOUNT` 是**账户数**比，不是资金比。
> "61.7% 的账户在做多" ≠ "61.7% 的钱在做多"——可能是大量小账户抄底、少数大账户做空。
> 只有 `TOP_POSITION` 是按持仓量加权的。判断资金方向请以 `TOP_POSITION` 为准。

**资金费率**（每 8 小时结算一次）：

| 费率 | 年化 | 含义 |
|---|---|---|
| > 0.02% | > 20% | 多头拥挤，持有成本高 |
| 0 ~ 0.01% | 0 ~ 10% | 中性 |
| < 0 | 负 | 空头拥挤，可能发生轧空 |

## 第 4 步：微观结构（1 分钟）

> ⚠️ **本步的两个数据我们都没有**：盘口深度需要实时 WebSocket 快照（未采集），
> 基差/premium 只有最新快照（`premium_index` 是快照表，无历史）。以下只能手工从
> 币安 App 或 Coinglass 看，不能写进脚本。

**盘口深度**（币安 App 合约页 → 数据 tab，或 Coinglass）：

- ±1% 区间内挂单总额 / 日成交额
- 比值 < 0.1% → **插针高危**，一笔几十万的单就能打穿 1%

**最近事件**：

```bash
java -jar ba-tools.jar ain-review --symbol XXXUSDT --hours 72 --out .
```

看过去 72 小时有没有大振幅事件，以及事件后价格怎么走的。

## 第 5 步：对手盘在哪（3 分钟）

这一步决定「谁会被先打爆」。

**强平距离公式**（逐仓）：

```
多单强平价 ≈ 开仓价 × (1 − 1/杠杆 + 维持保证金率)
空单强平价 ≈ 开仓价 × (1 + 1/杠杆 − 维持保证金率)
```

| 杠杆 | 强平距离 |
|---|---|
| 3x | ~33% |
| 5x | ~20% |
| 10x | ~10% |
| 20x | ~5% |
| 50x | ~2% |

**判断**：
- 空头成本区在现价上方 10%，且空头仓位大 → 拉升会引爆轧空
- 多头成本区在现价下方 15%，且多头拥挤 → 下跌会连环爆仓

**关键**：强平价是可被算出来的公开信息。你的止损别放在大众位置（整数关口、前低正下方 1–2%）。

## 第 6 步：决策矩阵

| 阶段 | 拥挤方向 | 价格位置 | 结论 |
|---|---|---|---|
| 吸筹 | 中性 | 低分位 | **观察池**，等放量突破再进 |
| 吸筹 | 空头拥挤 | 低分位 | **最佳做多窗口**，小仓试 |
| 试盘 | 任意 | 任意 | 等确认，不猜方向 |
| 拉升 | 空头拥挤 | 中位 | 可跟，但止损要紧 |
| 拉升 | 多头拥挤 | 高分位 | **不追**，等回踩 |
| 派发 | 多头拥挤 | 高分位 | **回避**，或等破位做空 |
| 砸盘 | 多头已爆 | 低分位 | 等 24–48h 企稳，别接刀 |
| 冷却 | — | — | 跳过 |

---

## 第 7 步：下单与风控

| 项 | 规则 |
|---|---|
| 杠杆 | ≤ 3–5x，逐仓 |
| 强平价距离 | ≥ 3 × ATR（或 ≥ 20%） |
| 止损位 | 放结构位（前低 −3%、或 ATR 下沿），不放整数关口 |
| 单笔风险 | ≤ 本金 1–2% |
| 加仓 | 只在浮盈时加，不在浮亏时补 |
| 检查清单 | 下单前确认：阶段不是派发、费率不是极高、盘口不是极薄 |

## 红旗清单（看到就别碰）

1. **距上市 < 7 天**：没有历史，全是情绪
2. **日成交额 < 500 万 U**：进出都是问题
3. **±1% 深度 < 5 万 U**：一笔单就能插针
4. **资金费率年化 > 100%**：多头极度拥挤，随时被收割
5. **大户持仓比 > 3 且散户比 < 0.3**：典型的「待收割」结构
6. **过去 24h 振幅 > 40%**：波动不可控，止损必被扫
7. **阶段 = 派发 + OI 距峰 < −20%**：货已经出得差不多了

## 时间预算

| 档位 | 步骤 | 耗时 | 适用 |
|---|---|---|---|
| 快速分诊 | 1 + 3 | 3 分钟 | 刷榜、扫群消息 |
| 标准评估 | 1 + 2 + 3 + 6 | 10 分钟 | 准备下单前 |
| 完整尽调 | 全部 | 30 分钟 | 重仓、或长期跟踪 |

---

## 常见误判

- **把「OI 名义值」当仓位**：`sum_open_interest_value` 会随价格膨胀，判断加减仓必须用币数
- **把「账户数多空比」当资金**：散户人多钱少，与名义比经常反向
- **把「缩量上涨」当强势**：没有买盘接力，多为诱多
- **把「暴跌后反弹」当拉升**：距高 < −40% 的反弹是超跌修复，不是主升浪

## 附：阶段识别的实现（v2）与回测结论

### v2 相对 v1 的五个修正

| 问题 | v1 | v2 |
|---|---|---|
| 阈值口径 | 全市场绝对值（量比 >1.5） | 自身 90 天 **z-score**（量比 z>1） |
| 时间尺度 | 只用 1h 派生特征 | 日线判定 + 7 天趋势校验，冲突时标注 |
| 基准 | 无 | 同时输出相对 BTC 的 7 日超额收益 |
| 可信度命名 | “置信分”（误导） | “匹配度”（明确不是概率） |
| 可检验性 | 无 | 每个判定附**证伪条件** |

### 回测：阶段标签有没有预测力？

样本：536 个币、回看 120 天、每日采样、特征只用当日及之前的数据（无未来函数）。

**基线**（全部样本）7 日中位数 -1.26%，胜率 44.5%。

| 阶段 | 样本 | 7d 中位数 | 胜率 | 相对基线 |
|---|---|---|---|---|
| 拉升 | 1798 | -1.36% | 44.8% | -0.10 pp |
| 试盘 | 1762 | -1.65% | 44.6% | -0.39 pp |
| 派发 | 6555 | -0.82% | 44.5% | +0.44 pp |
| 砸盘 | 1244 | -1.20% | 46.5% | +0.06 pp |
| 吸筹 | 16092 | -1.53% | 43.4% | -0.27 pp |
| 冷却 | 31543 | -1.19% | 44.9% | +0.07 pp |

**加入日期聚类后（不重叠采样，8729 样本 / 90 个交易日）：**

| 阶段 | 样本 | 7d 中位数 | vs 基线 | 90% CI（日期聚类） |
|---|---|---|---|---|
| 拉升 | 208 | -2.14% | -1.17 pp | [-3.34, +1.42] |
| 试盘 | 288 | +1.09% | +2.06 pp | [-1.31, +4.56] |
| 派发 | 869 | -0.07% | +0.91 pp | [-0.65, +2.19] |
| 砸盘 | 232 | -0.80% | +0.18 pp | [-1.92, +1.85] |
| 吸筹 | 2437 | -1.36% | -0.38 pp | [-1.40, +0.39] |
| 冷却 | 4695 | -1.03% | -0.05 pp | [-0.47, +0.55] |

**所有置信区间都跨 0。** 「试盘 +2.06pp」按事件数算约 2.9σ（看着显著），
但同一天几百个币走势高度相关，按交易日整群重采样后区间是 [-1.31, +4.56] —— 不显著。

**结论：阶段标签没有可用的预测力。** 它的正确用法是**状态描述**（现在长什么样），不是**方向预测**（接下来涨还是跌）。

### 那系统还剩什么价值

1. **异常告警**：OI 单小时掉 10%、费率年化破 100%、24h 振幅超 30% —— 这类不需要预测，只需要及时。
2. **记录与归因**：把每日快照落表，三个月后能回答“我的判断准不准”。
3. **排除法**：虽然不能告诉你该买什么，但能告诉你“这个币现在没有结构”，省掉盯盘时间。
